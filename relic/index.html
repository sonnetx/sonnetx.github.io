RELIC

A benchmark that measures whether coding agents implement the language a manual specifies or the language their pretraining taught them.

September 2026 · CodeResultsLong version

Anthropic's C compiler project showed that a team of agents can sustain a large engineering effort, with 16 parallel agents working across roughly 2,000 sessions to produce a working C compiler (Anthropic, 2026). Chris Lattner read the project's source history and found a design that reproduces the GCC and LLVM lineage in every subsystem. He also found that the compiler hard-codes what its own tests need, and he concludes that it will not generalize beyond its test suite (Lattner, 2026). Neither observation can be measured on C. C is among the best-represented languages in any training corpus, so a correct C compiler is equally consistent with reading the standard and with recalling an existing implementation.

Choosing an obscure language does not fix the problem, because claims about how often a language appears in training data are unfalsifiable, so RELIC generates the language instead. It starts from B, the 1972 predecessor of C (Thompson, 1972), and treats 18 of its design decisions as knobs, among them the quote character for strings, the meaning of each arithmetic operator, the resolution of the dangling else, and whether a pointer steps by a word or a byte. A seeded generator permutes some of the knobs. Every variant stays exactly as complex as B, and habits learned from C give wrong answers in it. The same definition renders a self-contained manual of about 2,000 lines and configures the reference interpreter that grades the compiler, so the manual and the oracle cannot disagree.

The agent receives the manual, the specification of a small stack machine to compile to, and 22 example programs with their expected outputs. It writes a compiler in Python and gets four rounds of feedback on the examples, and we score the best round's compiler against the interpreter on 100 hidden programs that every condition shares. We test the base language and four variants, which change two lexical knobs, two syntactic knobs, two semantic knobs, or eight knobs across all three classes. A reference compiler that reads the variant definition passes every hidden program in every condition. A compiler that ignores the manual and assumes B passes only the programs whose meaning the variant leaves unchanged, which is 8% of the suite on the semantic variant and none of it on the combined variant.

Run-to-run variance

Our first sweep ran Gemini 3.1 Pro and Gemini 3.7 Flash once per condition, and Flash passed every hidden program on all four counterfactual variants. Three further runs per cell retract that result. The median spread between runs of one model on one condition is 50 points, and the largest spread is 100 points. On the semantic variant, Flash scores 0, 11, and 100 with the same manual and the same prompt.

At three runs per cell, only differences whose ranges do not overlap support a claim. Pro's ranges on the semantic variant (0 to 15) and the combined variant (1 to 25) lie entirely below its range on the base language (29 to 100). Flash passes every hidden program in all three runs of the lexical and syntactic variants, so changes of spelling and grammar cost it nothing measurable. The data leave every other comparison unresolved, and a leaderboard built from single runs at this task size would rank models on noise.

Use of the manual

The examples include expected outputs, and feedback reports what a failing program should have printed, so a model could infer the permuted semantics without reading the manual. We ran an ablation that removes both channels, which leaves the manual as the only source of the semantics. Five of six ablated Flash runs pass at least one hidden program, and three reach all 100, on variants where the compiler that assumes B scores 8% and 0%. Those three compilers use information that exists only in the manual.

The clearest case of the opposite behavior comes from Qwen3.5 9B, whose compiler fails every hidden program, as do the compilers of every open-weight model we tested from 7B to 32B parameters. On the combined variant, its compiler maps the plus sign to addition, the minus sign to subtraction, and the slash to division, which are B's meanings. The manual assigns those three spellings division, addition, and subtraction. The model's reasoning trace runs to about 100,000 characters and never mentions the operator table. It read the manual of a language absent from any training set and wrote a compiler for B.

Test-suite coverage

A test suite certifies only the rules its programs decide, so for each knob value we counted the hidden programs whose meaning changes when only that knob changes. The suite decides no program for the string terminator, the byte unit of pointer arithmetic, left-to-right argument evaluation, or one of the truth rules. The semantic variant changes two knobs, the arithmetic table and the pointer unit, and the arithmetic table decides all 92 of the programs that distinguish that variant from B. A compiler that implements the table and ignores the pointer unit therefore passes every hidden program on that variant, and two Flash compilers with perfect hidden scores do exactly that.

We grade a separate diagnostic rubric of 42 single-feature programs, which we repaired after an earlier audit so that every knob value has an item that a compiler assuming B fails. The rubric catches both compilers on the two items that step a pointer by one element in the manual's unit. The hidden suite misses the error because a one-word pointer step is misaligned under byte addressing and traps. A program that must run under every variant can therefore step a pointer only in each variant's own unit, and our program generator has no construct for that step.

Generalization beyond the visible tests

A candidate sees 22 example programs, and we score it on 100 it never sees, so the difference between the two pass rates measures the test-suite fitting that Lattner inferred from the C compiler's source. The gap is largest where the manual contradicts convention about what the operators compute. Averaged over four runs, Pro's compilers for the semantic variant pass 88% of the example programs and 12% of the hidden ones. Of the 26 runs that pass every example, 24 also pass every hidden program, one passes 55%, and one passes none.

Feedback on the examples does not improve a compiler monotonically, since a round of feedback lowers the example score in 12 of 48 working runs and 8 runs end below their own best. The scaffold therefore keeps the best round's compiler instead of the last.

Limitations

We run three seeds per cell, which resolves only differences with non-overlapping ranges. A 100-program suite bounds each estimate no more tightly than about ten points. We test one base language, one scaffold, and one compute budget. We have not yet regenerated the hidden suite, so its scores say nothing about the four rules it fails to decide. We are adding generator constructs for those rules, after which we can rescore every saved compiler from disk without new model calls. The repository holds the benchmark, the interpreter, and every compiler these numbers come from, and the long version of this write-up has the full tables.
