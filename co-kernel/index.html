The faster kernel was slower

Kernel benchmarks time one kernel on an empty GPU, then keep whichever finished first. The GPU a kernel actually runs on is usually doing something else at the same time.

On one H100 at Stanford's Sherlock cluster, two kernels an agent wrote for the same matrix-vector multiply traded places. Alone, a 512-thread scalar kernel took 66.6 microseconds and a 256-thread vectorized kernel took 82.4, so the scalar kernel led by 24%. A neighbor holding 127 registers per thread, about half the register file, stretched those times to 143 and 131 microseconds. The old leader was then 10% behind.

Kernel Alone Shared Slowdown
512-thread scalar 66.6 µs 143.0 µs 2.15×
256-thread vectorized 82.4 µs 130.5 µs 1.58×

The ranking flips because the faster kernel is also the more fragile one, and by more than its original lead. Here that ratio is 2.15 / 1.58 = 1.36, against an isolated margin of 1.24. Slowing both kernels by the same amount leaves the order alone. An earlier set of near-duplicate kernels, the two fastest for each problem, never flipped, for that reason.

This is one pair, measured once, on one H100, beside a neighbor that only burns registers. Both kernels passed a correctness check in the same process, and the shared timings do not overlap between their 10th and 90th percentiles. It is an existence result. A leaderboard taken on an idle device is a property of the kernel and of whoever else is on the GPU.
